How it works · 05 min read

โมเดลจิ๋วที่อ่านที่อยู่
ทีละตัวอักษร

ตัวแยกที่อยู่ตัวนี้ไม่ได้เดาทั้งก้อนในครั้งเดียว มันหา location tuple จาก gazetteer ก่อน จากนั้นให้ Tagger ติดป้ายให้ตัวอักษรทุกตัวว่าเป็นชื่อ เบอร์ ที่อยู่ หรือชื่อพื้นที่ แล้วค่อยแปลงป้ายเหล่านั้นกลับเป็น 7 fields ทั้งหมดเป็นการบวกเลขจำนวนเต็มใน browser

คำถามที่หน้านี้จะตอบโมเดลขนาด 75 KB (gzip) ที่ไม่มี neural network แยกที่อยู่ไทยได้อย่างไร และมันยังแพ้กฎที่เขียนมือตรงไหน

01 · Two parsers

กฎที่เขียนมือ กับโมเดลที่เรียนจากตัวอย่าง

ในแพ็กเกจมี parser สองตัวที่ใช้ gazetteer ชุดเดียวกัน Candidate Engine คือ baseline ที่เขียนกฎด้วยมือ ส่วน Tagger คือโมเดลที่เรียนจากข้อมูลสังเคราะห์ ปัญหาที่เหลืออยู่ส่วนใหญ่คือขอบเขตของชื่อกับที่อยู่ ซึ่งเป็นงานตัดช่วงข้อความ กฎรายคำจึงตามไม่ทัน

Candidate Engine

เสนอช่วงข้อความที่เป็นไปได้หลายช่วง ให้คะแนนจากหลักฐานที่เขียนเป็นกฎ แล้วเลือกชุดที่ไม่ทับกัน

generateCandidates(raw)
score(evidenceRules)
prune(no-overlap, location-coherence)
validate(or abstain)

Tagger

ไม่เสนอผู้สมัคร แต่ตัดสินทีละตัวอักษร แล้วบังคับว่าแต่ละ field เป็นช่วงต่อเนื่องได้ช่วงเดียว

anchor(raw)          → tuple + flags
featurize(raw, flags) → 58 features / char
decodeTags(features)  → tag / char
resolve(spans, tuple) → 7 fields

04 · Hashed features
ตัวอักษรหนึ่งตัวมองเห็นอะไรบ้าง
ระบบไม่ตัดคำภาษาไทย มันมองหน้าต่างตัวอักษรรอบตำแหน่งนั้นหลายขนาด จึงรับคำติดกัน คำย่อ และ typo บางส่วนได้ ตัวเลขทุกตัวถูกมองเป็น 0 ตัวเดียวกัน เลขไทยกับเลขอารบิกจึงให้ feature เดียวกัน

        

          
นอกจากหน้าต่างเหล่านี้ยังมีรูปร่างของข้อความ (ไทย ตัวเลข ช่องว่าง ขึ้นบรรทัด) ความยาวของกลุ่มตัวเลข ตำแหน่งในบรรทัด บริบทไกล 4 ถึง 14 ตัวอักษร และ flag จาก Anchor รวม 58 features ต่อตัวอักษร

          
score[tag] += weights[hash(key) × 8 + tag]
ทุก feature คือ string สั้น ๆ เช่น t-1:กลน ที่ถูก hash ลง 32,768 ช่อง แต่ละช่องเก็บน้ำหนัก int8 จำนวน 8 ค่า หนึ่งค่าต่อ tag คะแนนของตัวอักษรคือผลบวกของ 58 แถว ไม่มีการคูณทศนิยม ไม่มี model server และไม่มี training ตอนใช้งาน
โมเดลทั้งตัวคือ Int8Array ขนาด 262,144 ค่า กับตาราง transition 8×8

        

      


      

        
05 · Size against accuracy
เล็กได้แค่ไหนก่อนจะเริ่มพลาด
เลื่อนเพื่อเปลี่ยนจำนวนช่อง hash ตัวเลขคือ exact record เฉลี่ยจากการ train 5 seeds ต่อขนาด เทียบกับ Candidate Engine บนชุดเดียวกัน ทุก record ต้องถูกครบทั้ง 7 fields จึงนับว่าถูก

06 · Where it still loses
สิ่งที่ตัวเลขข้างบนยังไม่ได้บอก
Tagger ชนะบนข้อมูลสังเคราะห์ที่กันไว้ แต่ยังแพ้ Candidate Engine บน messy fixture 15 ต่อ 17 จาก 20 records

        

          
ข้อมูล train เป็นข้อมูลสังเคราะห์ทั้งหมด
Tagger เรียนรูปแบบที่ generator สร้าง เมื่อเจอ layout ที่ generator ไม่เคยสร้าง เช่น จังหวัดขึ้นก่อนแล้วบ้านเลขที่อยู่ท้ายสุด ขอบเขตของ field จะเลื่อน ตัวอย่างที่สามในข้อ 02 คือกรณีนี้ โมเดลอีกตระกูลหนึ่ง (convolution 45k parameters) ได้คะแนนเท่ากัน ตัวจำกัดจึงเป็นความหลากหลายของข้อมูล

          
Candidate Engine ถูกพัฒนาบน fixture ชุดนี้
กฎถูกปรับจนผ่าน 20 records นี้ ส่วน Tagger ไม่เคยเห็น หนึ่ง record มีน้ำหนัก 5 จุดร้อยละ และรายการจริง 58 records ที่ใช้เป็นเกณฑ์รับงานยังไม่ได้รันกับ Tagger แพ็กเกจจึงยังเก็บ parser ทั้งสองตัวไว้

        

      


      
The mental model
gazetteer ให้ตัวตน โมเดลให้ขอบเขต
ชื่อตำบล อำเภอ จังหวัด และรหัสไปรษณีย์มีคำตอบที่ถูกอยู่แล้วใน gazetteer จึงไม่ต้องให้โมเดลเดา โมเดลทำงานเดียวคือบอกว่าตัวอักษรไหนอยู่ใน field ไหน ซึ่งเป็นส่วนที่กฎรายคำทำได้ไม่ดี
  • ไม่มี runtime training หรือ API
  • inference คือการบวกเลข int8 กับ Viterbi หนึ่งรอบ
  • train ใหม่ได้ใน 4 วินาทีด้วย Bun
  • parser สองตัว benchmark เทียบกันได้ด้วยคำสั่งเดียว
